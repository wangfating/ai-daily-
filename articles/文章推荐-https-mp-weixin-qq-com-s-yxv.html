Codex 装完别急写代码，先装这 5 个 Skill

刚装完 Codex 直接上手写代码，结果往往是"改了三遍还不对"。这篇文章告诉你：差一步就是没装 Skill。5 个社区公认的 Skill，能让你的 Codex 从"瞎写"变成"按规矩办事"。

📌 这篇文章说了什么

刚装完 Codex 的新手，往往兴冲冲打开终端打了第一句"帮我写个登录页面"，结果出来的代码又泛又乱，改了三遍还不对。问题出在哪？你可能漏了一步——装 Skill。

这篇文章只回答一个问题：刚装完 Codex 的新手，应该装哪几个 Skill、怎么装、装完有什么变化。 文章介绍了 5 个社区公认的"刚需" Skill，分别解决"没想清楚就动手"、"会话崩溃丢进度"、"Codex 乱改代码"、"长任务接不住"、"联网搜不到最新信息"这 5 个高频痛点。每个 Skill 都附带了安装命令和使用场景，照着装就能用。

🎯 核心观点

  1. Skill 是 Codex 的"岗位手册"，不装它就等于裸奔。 Codex 默认靠猜你想干什么，装了 Skill 之后它按你定好的规矩做事，产出质量天差地别。
  2. grill-me 能逼 Codex 先想清楚再动手。 你跟它说"加个微信登录"，它不会直接写代码，而是追问 OAuth2 还是扫码、用户表有没有 openid 字段、老用户怎么绑定——把需求对齐了再开工。
  3. planning-with-files 让崩溃的会话也能无缝接续。 Codex 会话聊到后边越来越慢、越来越糊涂，这个 Skill 把计划和进度写到三个文件里，下次开新会话直接接着干。
  4. Karpathy Guidelines 用 4 条硬规则纠正 Codex 的三大毛病。 毛病包括：假设错了不问就动手、50 行能搞定非写 500 行、顺手"改进"不相关的代码。
  5. handoff 是长任务的"接力棒"，Firecrawl 给 Codex 装上实时联网。 会话太长就 handoff 开新会话，联网搜索用 Firecrawl 代替默认缓存，拿到的才是最新内容。

💡 深度解读

Skill 到底是什么？和 AGENTS.md 有什么区别？

Skill 就是一个 Markdown 文件，告诉 Codex 在特定场景下怎么做。装之前 Codex 就像没装任何 App 的新手机——能开机，但什么也干不好。装了 Skill 之后，Codex 自动遵守这些规则。

一个容易搞混的区别是 AGENTS.md 和 Skill 的范围不同：

对比维度 AGENTS.md Skill
作用范围 全局规则，相当于公司制度 特定场景指令，相当于岗位手册
生效条件 对所有任务生效 只在匹配到的时候才加载
适用场景 团队规范、全局约束 特定工作流（如写代码、规划任务）
例子 "不要删注释"、"代码必须通过 Lint" "写代码前先追问需求"、"只改必须改的文件"

Karpathy Guidelines 这个 Skill 就完美体现了这种区别：它只在 Codex 写代码的时候才加载，不会在你让它做别的任务时跑出来多嘴。如果把同样内容写进 AGENTS.md，那就是全局生效，所有任务都受约束，反而可能影响其他场景。

5 个核心 Skill 深度解析

Skill 1：grill-me — 写代码前先想清楚

Codex 最大的毛病是带着错误假设就动手。你跟它说"加个微信登录"，它直接开始写代码，基本不会追问你：微信登录用 OAuth2 还是扫码？用户表有 openid 字段吗？老用户怎么绑定？

grill-me 就是来治这个毛病的。它的核心指令很简单："Interview me relentlessly about every aspect of this plan until we reach a shared understanding."（这个计划的方方面面对我穷追不舍地追问，直到我们达成共识。）

使用场景：接到新需求、做重构、修 bug 之前——任何需要先想的场景。Reddit 上有用户说用了 grill-me 之后，"it completely changed how I plan with Codex"，感觉 90% 的情况能做出自己想要的结果。

Skill 2：planning-with-files — 崩溃了也能接着干

和 Codex 聊久了，会话会崩。上下文太长之后 Codex 变糊涂，改东忘西。/compact 能压缩上下文，但压缩完还是同一个对话，结构化的进度信息丢了。

planning-with-files 把你的计划和进度写到三个文件里：

  • task_plan.md：要做什么
  • findings.md：发现了什么
  • progress.md：做到哪了

下次开新会话，Codex 读这三个文件就能接着干，不从头来。

它和 handoff 的区别：handoff 是"拍快照走人"，快照拍完当前会话就结束；planning-with-files 是"边做边记"，整个工作过程中持续记录，每完成一步自动更新进度。

Skill 3：Karpathy Guidelines — 让 Codex 少干蠢事

Codex 最常见的三个毛病：

  1. 假设错了不问就动手
  2. 50 行能搞定非写 500 行
  3. 顺手"改进"不相关的代码

Karpathy Guidelines 把这三条行为纠正编成四条硬规则：

规则 英文原文 含义
先想再写 Think first, then code 有多种理解的时候列出来让你选，不偷偷选一个就跑
简单优先 Keep it simple 200 行能写完的别写 500 行，不加你没要求的功能
手术式改动 Surgical changes 只碰必须改的文件，不顺便"优化"旁边的代码
目标驱动 Goal-driven 定义成功标准，写测试验证，循环直到通过

这四条规则源自 Andrej Karpathy 今年 1 月分享的 AI 编码工作流观察。开发者 forrestchang 据此改写成 CLAUDE.md 格式，multica-ai 又做了跨平台 Skill 版本，GitHub 上超过 17 万 stars。

什么时候感觉最明显？改一个小 bug，结果 Codex 重构了半个文件——装了这条 Skill 之后不这么干了。

Skill 4：handoff — 会话接力棒

Codex 会话聊到后边，越来越慢，越来越糊涂。这时候你需要开个新对话，但前面的上下文怎么办？

handoff 把当前会话压缩成一份结构化的 markdown 文档，包含目的、上下文、建议的 skill、现有文件指针。你开个新对话，把这份文档丢给它，直接接着干。

和 /compact 的区别：compact 还是在同一个对话里压缩，对话还是那个越来越长的对话；handoff 是开新对话，把工作笔记带过去，从干净的状态重新开始。

Ben Holmes 分享过一个进阶用法：在 Claude Code 里用 grill-me 做完规划，然后 handoff 给 Codex 的多个 worktree 并行实现。新手先记住"会话太长就 handoff"就够了。

Skill 5：Firecrawl — 给 Codex 连上互联网

Codex 自带联网搜索，但默认走缓存，拿到的可能是几天前的内容。如果你的问题需要最新信息——比如刚发布的 API 变更、竞品最新的定价——缓存里的旧数据帮不上忙。

Firecrawl 给 Codex 装上实时联网能力：search（搜索）、scrape（抓取页面）、crawl（爬整站）、map（站点地图）、interact（操控浏览器）。不是搜缓存，是搜实时网页。

安装需要 API key，免费额度每月 1000 次，够日常用。有一点要注意：Firecrawl 的服务在国外，需要稳定的网络环境。

怎么装？两种位置两种场景

安装就一条命令的事，但有两种安装位置：

# 全局安装：放在 ~/.agents/skills/，所有项目都能用
npx skills add mattpocock/skills --skill grill-me -y -g

# 项目级安装：放在项目根目录的 .agents/skills/，随仓库走，团队共享
npx skills add mattpocock/skills --skill handoff -y

装完验证：看目录下有没有 SKILL.md

ls ~/.agents/skills/grill-me/SKILL.md

另外 Codex 内置了 $skill-installer，在 Codex 里直接输入这个命令，可以交互式选择安装官方仓库的 skill。不过它只收录了 openai/skills 仓库的 skill，社区 skill 还得用 npx skills add 安装。

装完怎么用？两种方式：输入 $skill-name 显式调用，或者你的任务描述匹配到 skill 的触发条件时自动加载。

🚀 如何实践

第一步：装上 5 个刚需 Skill（5 分钟搞定）

# 1. 写代码前先追问需求（全局安装）
npx skills add mattpocock/skills --skill grill-me -y -g

# 2. 记录任务进度，会话崩溃也能接着干（全局安装）
npx skills add OthmanAdi/planning-with-files -y -g

# 3. 纠正 Codex 三大毛病（全局安装）
npx skills add multica-ai/andrej-karpathy-skills -y -g

# 4. 会话太长就接力（项目级或全局按需）
npx skills add mattpocock/skills --skill handoff -y -g

# 5. 实时联网搜索（需要 API key）
npx -y firecrawl-cli@latest init --all --browser

第二步：装完验证

装完每个 Skill 后，跑一个简单任务验证是否生效。比如装完 Karpathy Guidelines 后，让 Codex 改一个小 bug，观察它会不会顺手"优化"旁边的代码——装了之后就不会了。

第三步：按需扩展

如果你觉得 5 个刚需还不够，下面这些可以根据工作流按需安装：

Skill 名称 功能 安装命令

skill-creator 交互式问答，帮你写自己的 Skill Codex 内置，输入 $skill-creator
agent-skill-creator 把你的工作流一键转为可复用 Skill，17 平台兼容 npx skills add FrancyJGLisboa/agent-skill-creator

    npx skills add mxyhi/ok-skills
  • claude-code-skills-zh（laolaoshiren）：200+ skill 中文合集，按场景分类

    npx skills add https://github.com/othmanadi/planning-with-files --skill planning-with-files-zh

进阶建议

  1. 先装 grill-me 和 Karpathy Guidelines，这两个对代码质量提升最明显。
  2. 长任务必开 planning-with-files，会话崩溃时你会感谢自己。
  3. 会话太长就 handoff，不要硬撑。
  4. 需要最新信息时用 Firecrawl，不要依赖默认缓存搜索。

💭 总结与推荐

这篇文章的价值在于：它把"装完 Codex 后第一步该干嘛"这件事讲清楚了。 核心结论是——装完别急写代码，先装 Skill。对于刚接触 Codex 的新手，这 5 个 Skill 能立竿见影地提升产出质量；对于有经验的用户，grill-me 和 Karpathy Guidelines 值得立刻装上。适合所有正在用 Codex 写代码、但总觉得"结果不够好"的人。
