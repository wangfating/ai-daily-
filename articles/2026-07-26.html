ECC：给你的 AI 编码助手装上"操作系统"

📌 项目是什么

你有没有遇到过这样的场景——用 Claude Code 写了一段代码，切换到 Cursor 又得重新适应它的规则；你在 Codex 里配置好的 prompt 最佳实践，到了 OpenCode 又全部作废。每个 AI 编码助手（harness）都有自己的"脾气"，你需要不断重复劳动来"驯服"它们。ECC 就是来解决这个问题的。

ECC 是一个面向 AI Agent 的性能优化系统（Harness Performance Optimization System）。它本质上是为各种 AI 编码助手量身定制的"操作系统层"——在 Claude Code、Codex、Cursor、OpenCode、Gemini、Zed、GitHub Copilot 等多个 harness 之上，提供统一的能力抽象：包括技能（Skills）、直觉（Instincts）、记忆优化、安全扫描和研究导向的开发工作流。作者 affaan-m 在过去 10+ 个月里高强度使用这些工具构建真实产品，将经验沉淀成了这个系统。截至发稿，它已获得超过 23 万 Star，是一个现象级的开源项目。

简单来说，ECC 让你写一次配置，就能在所有 AI 助手上生效——它把"人适应工具"的过程翻转成了"工具适应人"。

🎯 适用场景

  • 多工具并行开发：团队里有人用 Claude Code、有人用 Cursor、有人用 Codex，ECC 提供统一的 skills 和 rules，告别"每个工具一套配置"的混乱。
  • 企业级 AI 编码安全合规：ECC 内置安全扫描和策略执行，适合需要确保 AI 生成代码不触碰敏感数据、符合内部规范的场景。
  • 长期项目的知识沉淀：ECC 的记忆优化和持续学习机制，能把项目上下文、架构决策沉淀下来，让 AI 在后续会话中"记住"之前的讨论。
  • 快速启动新项目：通过预设的 skills 和 hooks，新项目可以一键获得经过验证的开发工作流，不需要从零配置。
  • MCP（Model Context Protocol）生态整合：ECC 帮你管理 MCP 服务器的配置，让 AI 助手无缝对接外部工具和数据源。

✨ 核心特性

  1. 跨 Harness 统一层：一套配置同时适配 Claude Code、Codex、Cursor、OpenCode 等 7+ 个 AI 编码助手，不再为每个工具单独维护规则。
  2. Skills 系统：可复用的技能模块，涵盖代码审查、调试、架构设计等常见任务，像插件一样即插即用。
  3. Instincts（直觉层）：基于项目上下文自动推断最佳实践，让 AI 在写代码时"自带经验"，减少反复试错。
  4. Memory Optimization：智能管理会话记忆，避免 AI 在长对话中"失忆"，保持上下文一致性。
  5. Security Scanning：集成安全扫描能力，在 AI 生成代码时实时检测潜在的安全漏洞和敏感信息泄露。
  6. Research-First 开发：内置研究导向的工作流，先探索再实现，适合复杂需求和新技术调研场景。
  7. Hermes Operator 架构（v2.0.0 新增）：提供公开的 Operator 故事层，让可复用的能力可以在不同 harness 间自由流转。
  8. GitHub App 集成：通过官方的 GitHub App（ECC Tools）直接在 Pull Request 流程中执行 AI 增强工作流，无需手动配置。

小结：ECC 的核心差异化在于"跨平台"和"系统化"。Cursor 和 Claude Code 各自有自己的规则系统，但它们是孤岛。ECC 把这些孤岛连接起来，形成统一的工作流。

🚀 快速上手

第一步：安装 ECC Universal（核心包）

# 通过 npm 安装 ECC Universal 包，这是跨 harness 的核心运行时
npm install -g ecc-universal

或者使用 npx 临时运行：

# 无需安装，直接运行（适合一次性任务）
npx ecc-universal init

第二步：初始化项目配置

# 在项目根目录运行，生成 .ecc/ 目录和默认配置
ecc init

执行后，项目结构会变成这样：

your-project/
├── .ecc/
│   ├── skills/        # 技能模块目录
│   ├── rules/         # 跨 harness 规则文件
│   ├── memory/        # 记忆与上下文存储
│   └── config.yaml    # ECC 主配置
├── .cursorrules       # 自动生成的 Cursor 规则
├── .claude/           # 自动生成的 Claude Code 配置
└── ...

第三步：选择你的 Harness 并启用对应插件

# 如果你使用 Claude Code
ecc enable claude-code

# 如果你使用 Cursor
ecc enable cursor

# 如果你使用 Codex
ecc enable codex

# 启用多个 harness（用空格分隔）
ecc enable claude-code cursor codex

第四步：使用内置 Skills

# 查看可用的技能列表
ecc skills list

# 安装一个代码审查技能
ecc skills install code-review

# 安装一个安全扫描技能
ecc skills install security-scan

第五步：验证安装

# 运行自检，确认所有 harness 连接正常
ecc doctor

输出示例：

✓ ecc-universal v2.0.0
✓ Claude Code adapter: connected
✓ Cursor adapter: connected
✓ 3 skills loaded
✓ Memory index: ready
✓ Security scanner: active

代码示例：在项目中添加自定义 Skill

在 .ecc/skills/ 目录下创建一个自定义 skill：

# .ecc/skills/my-api-best-practices.yaml
name: api-best-practices
description: 确保所有 API 端点遵循 RESTful 规范和项目内部约定
version: "1.0.0"

# 触发条件：当 AI 检测到路由/端点相关代码时自动激活
triggers:
  - pattern: "router|endpoint|api|route"
    languages: ["javascript", "typescript", "python"]

# 要注入的系统提示（instructions）
instructions: |
  你正在为项目编写 API 代码。请遵循以下规范：
  1. 使用 RESTful 命名约定（名词复数表示资源）
  2. 状态码必须正确：200/201/204/400/401/403/404/500
  3. 所有响应必须包含 `data` 字段包裹业务数据
  4. 错误响应格式：{ "error": { "code": "...", "message": "..." } }
  5. 必须包含输入参数校验

# 关联的 MCP 工具（如果有的话）
mcp_tools:
  - name: api-tester
    description: 调用本地 API 测试端点

启用后，每次 AI 助手检测到路由相关代码时，就会自动应用这些规范。

💡 使用建议

✅ 什么时候用

  • 同时使用多个 AI 编码助手：如果你在 Claude Code 和 Cursor 之间切换，ECC 能让你的配置一次编写、多处生效。
  • 团队协作项目：把 .ecc/ 目录纳入版本控制，团队成员共享同一套 AI 工作流规则，保证代码风格和质量的一致性。
  • 长期维护的项目：ECC 的记忆优化和持续学习机制，能避免 AI 在每次新会话中"从零开始"。
  • 需要安全合规的场景：内置安全扫描对金融、医疗、政务等对代码安全要求高的项目特别有价值。

❌ 什么时候不用

  • 单人只用单一 AI 助手：如果你只用 Cursor 且已经熟悉它的规则系统，ECC 的跨平台能力对你来说可能是多余的。
  • 极简项目/原型验证：对于几小时就能写完的小型脚本或 PoC，引入 ECC 的配置开销可能大于收益。
  • 完全不需要 AI 辅助编码：如果你偏好纯手动编码，ECC 的价值几乎为零。
